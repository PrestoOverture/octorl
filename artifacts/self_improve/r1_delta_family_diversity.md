# Delta Contract: Family Diversity (R1)

## Findings

File: src/tasks/tool_recovery/generator.py, lines 172-207

Families 4-9 are generated by a single template function `_designed_family()`.
All 6 families share identical value ranges, identical constraint formulas,
identical field layout (`{prefix}_window`, `{prefix}_workers`, etc.), and
identical invalid pools. Only the namespace prefix and trigger name differ.

This means dev/test families (6-9) are trivially predictable from train
families (4-5). The model only needs prefix substitution, not content
generalization. The spec (§7.2) requires dev/test to have unseen
"family-specific fields, state vars, value ranges."

## Failed Conditions

No numbered SC was violated, but the implementation contradicts the
experiment's generalization claim. Families 0-3 demonstrate the expected
diversity (different multipliers, inverse arithmetic, 3-way lookups, varying
threshold polarities, domain-specific names). Families 4-9 have none of this.

## Fix

Delete `_designed_family()` and replace the 6 family call sites (lines 202-207)
with individually specified families below. Preserve the existing helper
functions `_sv()`, `_field()`, `_conditional()`. Keep the variable names
STORAGE_SERVICE through NOTIFICATION_SERVICE and the FAMILIES list order.
